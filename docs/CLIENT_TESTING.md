# 多客户端统一验收

目标：普通用户安装 Skill 后直接提出视频任务；没有凭证时，Agent 引导到官网获取 Key，主动打开本地隐藏输入框。用户粘贴一次，助手完成握手验证并保存配置，检查当前工具后继续原任务；人工刷新只作为未加载连接时的兜底。

配置适配的自动化测试与真实客户端验收分开记录。自动化通过不代表所有客户端的 Skill 识别、操作系统弹窗、工具刷新都已实际验证。以下清单适用于测试人员，不需要作为额外提示词发给被测 Agent。

## 发布与安装前提

- 确认测试安装来源包含本次修改。仅修改本地源码不会更新 GitHub 默认分支或已经安装的 Skill。
- 发布测试：由维护者提交并合并后，从对应 GitHub 版本安装。开发测试：从本地完整复制三个 Skill 到客户端实际识别的用户目录，记录源码版本。
- 在不关联本 Skill 源码仓库的空白工作目录测试，避免 Agent 使用仓库示例字幕代替真实转写。
- 先关闭被测客户端。获得测试用户授权后，仅移除 Video Transcriber 这一个 MCP 连接和本产品的三个旧 Skill/重复副本，保留其他连接、用户设置及源码。
- 检查是否有旧环境变量、插件连接或其他 Profile 提供此服务的凭证。不要输出变量值或真实 Key，也不要撤销网站上的有效 Key。
- 重启客户端、新建对话后再安装。上一次对话缓存的工具名、已经配置过的 Key、只缺少一个 Skill 的安装都不能作为首次接入的测试前提。

## 普通用户首次接入

在新对话中只发正常安装请求：

```text
帮我安装这个 Skill：https://github.com/VideoTranscriberAI/videotranscriber-skills
```

安装完成后发送：

```text
帮我把这个视频整理成中文学习笔记：https://www.youtube.com/watch?v=e8WaTlzuid0
```

不要在提示词中告诉 Agent 必须选哪个 Skill、运行哪个脚本或弹出 Key 窗口；观察它是否自然完成路由。预期：

1. 识别缺少 MCP 连接，保留原视频链接与中文笔记要求。
2. 引导登录官网 API 控制台获取 Key，说明使用独立 API Quota。
3. 主动运行当前客户端的配置助手，弹出本地隐藏输入框。无法打开系统窗口时，给出可用的原生凭证表单或用户终端隐藏输入方式。
4. 粘贴一次并点击连接；Key 不出现在聊天、命令参数、工具输出、项目文件中。
5. 验证成功后保存当前客户端的用户配置，先发现当前工具；工具已经可用时直接继续，不要求人工刷新或重启。只保存文件时不能声称运行中的 Agent 已连接。
6. 若工具尚未加载，宿主有重载能力时先使用并重新检查；没有重载能力或仍不可用时，给出具体人工刷新步骤。继续同一任务，读取转写结果并生成笔记，不要求用户手动搬运转写文本。

这个公开视频约 110 秒；基础转写会创建真实任务，预期按两分钟计费，以服务实际 `usage` 为准。连接握手不创建任务、不消耗转写 Quota。

## 失败与恢复

| 场景 | 预期 |
| --- | --- |
| 取消输入 | 保留原配置，不创建转写任务 |
| 输入空值或带换行等无效字符 | 提示重新复制，只在本地输入；不写配置 |
| API 明确返回无效/已撤销 Key | 提示使用有效 Key，通过同一本地入口替换 |
| 网关返回 HTML 或非 API 的 401/403 | 提示访问被网关/策略拒绝；不误报 Key 无效，不要求反复换 Key |
| API 账户被停用 | 指向 API 账户状态/支持，不引导购买网站套餐或换 Key |
| 临时网络/响应异常 | 同一进程最多验证三次，只输入一次；耗尽后保留原配置，不保存未经验证的 Key |
| 已保存且自动加载连接 | 直接继续原任务，不要求人工刷新或重启 |
| 执行/网络/配置权限不足 | 在再次收集 Key 前处理相应权限，不盲目重试 |
| 多 Profile/多个编辑器 | 输入前确定当前配置；不得写入闲置 Profile |
| 输入时另一个进程改了配置 | 报告配置并发变化，保留对方修改 |
| 重启后再次使用 | 复用保存的有效 Key，不再要求粘贴 |
| 直接分析已有 SRT/文字 | 不要求 Key，不创建转写任务 |

## 维护者验证与记录

```bash
python3 scripts/validate_repository.py
python3 -m unittest discover -s tests -p 'test_*.py'
```

真实网关检查使用固定无效测试值发起 `initialize`：带助手客户端标识应得到 API 的 `401 invalid_api_key`，而不是网关拦截。不要为检查连接创建转写任务；真实 Key 只在用户本地私密输入中完成最终验收。

每种客户端记录：系统/版本、安装来源版本、Skill 触发、Key 窗口、一次输入下的验证重试、自动继续及必要时的刷新兜底、重启复用、取消/错误路径。只记录脱敏状态、错误码和任务 ID，不记录 Key、完整配置或签名下载链接。

## 同类问题检查规则

- HTTP 401/403 必须结合服务的结构化错误码判断；网关拒绝不等于凭证失效。
- 离线模拟响应覆盖不到真实网关策略，发布前补一次不含真实凭证的生产握手检查。
- 配置文件存在不代表它属于当前 Profile；多 Profile 时先确定生效位置。
- 升级须确认已安装文件真的更新，避免安装器跳过已有 Skill 造成版本混用。
- 这些规则适合放在本项目的测试与接入说明中，不应扩展成所有项目的通用业务限制。
